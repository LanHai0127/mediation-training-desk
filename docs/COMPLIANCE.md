# COMPLIANCE · 合规红线与兑现位置

> 规则：每加一个页面 / 一份文书模板，回本文件对一遍。任何一条没兑现，不允许进入下一阶。
> 状态列只写两种：`已落位`（代码里能指到行）· `待落位`（S 阶段计划内）。

## 一、红线逐条

| # | 红线 | 具体做法 | 在哪兑现 | 状态 |
|---|---|---|---|---|
| 1 | 数据全部虚构 | 案卷、姓名、身份证号、地址、电话、笔录一律编造；不使用任何真实案件、真实当事人信息 | `src/cases/*` 全部为手写虚构数据；数据库不接任何外部数据源；提交前跑 `tools/audit_privacy.py` 扫真实姓名/手机号/身份证格式 | 待落位（S4） |

## 二、三条容易漏的

| 项 | 为什么容易漏 | 防法 |
|---|---|---|
| 打印/导出路径 | 网页上有角标，`print` 打出 PDF 就没了 | 打印样式单独写一份，角标与页脚都用 `position:fixed` + `@page` 保住；S6 验收时真打一份看 |
| 截图与演示视频 | 录屏时角标被裁掉 | 角标放右上角安全区内，录屏分辨率固定 1920×1080 不裁边 |
| README 与 PPT | 文案里出现真实单位、真实法条错号 | README 与 PPT 定稿后跑一次法条号核对（对着 `src/rag/laws/` 的 id 逐个比） |

## 三、验收动作（每次提交前）

1. 打开首页 → 角标在不在？
2. 点进登录页 → 声明在不在？
3. 走完一案 → 协议书页脚在不在？
4. 导出复盘报告 → 页脚在不在？
5. 跑 `tools/audit_privacy.py` → 0 命中？
6. 查部署日志 → 有没有出现人名/对话原文？
