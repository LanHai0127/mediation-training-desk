# 场景拾取修复说明（`src/web/scenes/scene3d.js`）

> 2026-11-05。这份说明只讲三件事：两处**已知根因**怎么修的、为什么 `passable` 物件不再挂
> `propId`、以及修完之后宿主侧 `repairPickable()` / `pickTargetAt()` 为什么可以安心当兜底。
> 以后谁想改回去，先看第 3 节。

## 0. 一句话

`scene3d.js` 自己修好"人物不在 pickable 里"和"pick 取 hits[0]"之后，宿主的
`repairPickable()` 实测移动 **0** 个节点，`pickTargetAt()` 仍会跑但不再需要替场景补行为；
`app.js` 一行未改。

## 1. 根因一 · 人物被 reparent 回 Scene 根

**位置**：`scene3d.js` 建人物组那段（`people` 循环）。

**改前**（每一步都先加进 pickable，紧接着又被 `scene.add` 摘走）：

```js
for (const c of opts.characters || []) {
  const g = makePerson(c);
  if (!c.ambient) {
    g.traverse((o) => { if (o.isMesh) { o.userData.personId = c.id; } });
    pickable.add(g);
    people.set(c.id, g);
  }
  scene.add(g);            // ← THREE 的 add() 会先把 g 从 pickable 摘下来
}
```

**改后**（只在没有 pickable 父级时才加进 Scene；ambient 显式给了 `personId` 才按 NPC 接进来）：

```js
const pid = c.personId || (c.ambient ? "" : c.id);
if (pid) {
  g.traverse((o) => { if (o.isMesh) { o.userData.personId = pid; } });
  pickable.add(g);
  people.set(pid, g);
} else {
  scene.add(g);
}
```

**为什么**：`pickAt()` 只对 `pickable.children` 做射线；人物被挂回 Scene 根之后，点人永远
命中不到，只会退化成"走到脚下地面点"。改后人物留在 pickable 里，`goToPerson → walkTo →
person:click` 这条原链路直接成立。

## 2. 根因二 · `pickAt()` 取 `hits[0]`

**位置**：`scene3d.js` 的 `pickAt()`。

**改前**：

```js
const hits = ray.intersectObjects(pickable.children, true);
if (hits.length) { return hits[0].object.userData; }
return {};
```

**改后**：遍历命中，取**第一个带 `personId` / `propId` 的**；没有身份的（家具描边
`LineSegments`、墙、底座等）跳过；`size.y < 0.35 && max(size.x, size.z) > 8` 的**地形**
命中按"地面点"处理（`continue`，最终落到 `groundAt()` 走位），不当家具：

```js
for (const h of hits) {
  const u = (h.object && h.object.userData) || {};
  if (u.personId) { return u; }
  if (!u.propId) { continue; }
  let flat = false;
  try {
    box.setFromObject(h.object);
    box.getSize(size);
    flat = size.y < 0.35 && Math.max(size.x, size.z) > 8;
  } catch (err) { flat = false; }
  if (flat) { continue; }
  return u;
}
return {};
```

**为什么**：家具的描边线比表面更近、userData 里没有 `propId`。拿 `hits[0]` 会拿到空身份，
点物件就退化成"走到地面点"，`goToProp` / `spot:click` 都不发。跳过无身份命中之后，命中的
第一件有身份的东西就是家具/人本身。

**配套（同一处命中的下一跳）**：`pointerup` 里原来写的是未声明的 `props.find(...)`，宿主
在 `app.js` 里塞了个 `w.props = { find: () => ({ interact: true }) }` 垫片才没炸。现在改成
场景自己的 `propById.get(hit.propId)`，并检查真实 `p.data.interact`：

```js
const p = propById.get(hit.propId);
if (p && p.data.interact) { goToProp(hit.propId); return; }
```

影响：① 单独打开 `scenes/*.html` 不再抛 `ReferenceError`；② 场景不再依赖宿主垫片；
③ 真正"没有交互点"的家具会走点击处地面，而不是被钉在默认交互点。宿主那条兜底仍会调
`goToProp`，所以在 `app.html` 里的最终行为不变。

## 3. 为什么 `passable` 的物件不挂 `propId`（**别改回去**）

**位置**：`scene3d.js` 建 prop 的那段。

```js
if (!p.passable || p.interact) {
  mesh.traverse((o) => { if (o.isMesh) { o.userData.propId = p.id; } });
}
```

**这不是顺手改的，是"可点的东西"的语义边界**：

- `passable: true` 表示"不挡路、可以从上面/下面穿过去"，绝大多数是地面贴片、雾片、
  藤蔓、玉米串、挂件、草垫、脚印这类**布景**；
- 它们没有 `interact`，本来就不是可查看的家具。旧代码给它们也挂 `propId`，后果是
  `pickTargetAt()` 会把它们当家具返回，点击地面/雾片时走到某个**固定交互点**，还会把
  `s_vine` 这类布景 id 记进 `state.seen`；
- `test_app.py` 的 K6 就是被这条旧语义绊住的：K4 点"纯地面"实际落在 `s_fog`（10×4.8 的
  雾片）上，旧代码 `goToProp('s_fog')` 把镜头带偏，K5 下一个"第一个可见 prop"变成
  `s_vine`（非证据点），K6 自然收不到证据。改后 K5 自然落到 `s_wallOld`（→ `f_wall`），
  K6 稳过。

**边界**：`propById` 仍然保留**全部** prop（含 passable），所以

- `goToProp(id)` / `__mini` 的 API、测试脚本、`info().props` 计数都不变；
- 变的只是"能不能被鼠标点中"这一层：passable 布景和 `g_*` 地面一样，点到就走过去，
  不再冒充家具。

以后如果某个 passable 物件真的需要交互，给它加 `interact` 即可（`|| p.interact` 会
重新挂上 `propId`），**不要**为了让它可点而删掉这个条件。

## 4. ambient 人物补 `personId`

`src/web/scenes/duty.js`（S0）里两个只有背影的布景人物：

| 场景 id | personId | 身份 |
|---|---|---|
| `amb_wait` | `npc_old_lady` | 等人的老太太 |
| `amb_caller` | `npc_young_man` | 打电话的年轻人 |

它们不是本案当事人，所以用 `npc_` 前缀；宿主 `pickTargetAt()` 认 `personId` 就能接住
点击，`openDialog()` 会给出"这个人不是本案当事人"的提示，不会开出错误的问话面板。
`ambient: true` 保留（默认仍是氛围人物），只有显式给了 `personId` 才进 pickable / people。
其它场景的 ambient 人物按"氛围人物"保持原样，运行时已支持以后按同一规则补 id。

- 直接打开 `duty.html`（**没有** app.js / repairPickable / pickTargetAt）：真实鼠标点老太太
  → `arrived (-3.45, 1.05)` + `person:click npc_old_lady`；点白板 → `arrived (-2.46, -2.91)`
  + `spot:click s_board`；`window.__err` 全程为空。

  点值班台 → `spot:click s_desk`、`state.seen` 增加；院墙点张守义 → 5 话题面板；
  点界石 → `state.seen` 增加 `f_marker`。
- `repairPickable()`：人物已在 pickable 里，实测移动 **0** 个节点（`__pickRepaired` 仍置位，
  幂等保护不变）——宿主兜底退化为 no-op。
