# 部署说明（材料已备齐，云上还没落地）

> 现状：**本地可运行、可演示**；云端部署按要求本轮不做。下面这份是照着能用就行的标准写的，
> 真要上线时按顺序执行即可，不用再设计。

## 一、运行形态

| 项 | 值 |
|---|---|
| 进程 | 单个 Python 进程，标准库零依赖（Python 3.10+） |
| 端口 | 8770 |
| 静态资源 | `src/web/`，由同一进程服务 |
| 数据 | `src/cases/*/case.json`、`src/laws/laws.json`（纯 JSON，随代码发布） |
| 运行态 | `src/auth.state.json`（登录失败计数）、内存会话；不需要数据库 |
| 探针 | `GET /__ver`（构建戳 + git 短 hash）、`GET /api/health` |

## 二、只加不改的部署流程

```bash
# 1) 新目录起新版本（不碰线上正在跑的目录）
rsync -a --exclude 'auth.local.json' --exclude 'auth.state.json' \
      ./ user@host:/opt/tiaojietai/releases/2026xxxx-1/

# 2) 新端口试跑
cd /opt/tiaojietai/releases/2026xxxx-1/src
TJ_PORT=8771 python3 server.py --host 127.0.0.1 --port 8771 &

# 3) 探针验证「跑的就是刚部署的那份」
curl -s http://127.0.0.1:8771/__ver      # build 时间戳与 git 短 hash 必须与刚发布的提交一致
curl -s http://127.0.0.1:8771/api/health | head -c 200

# 4) 切 systemd 指向（改 softlink 或 unit 里的 WorkingDirectory），reload
systemctl reload-or-restart tiaojietai

# 5) 再验一次探针，然后才确认切完
curl -s https://<域名>/__ver
```

回滚：把 softlink 指回上一个 release，`systemctl restart tiaojietai`，再验探针。
**判据是探针变了才算切完**——探针没变说明进程没重启，等于没切。

## 三、systemd 单元（`deploy/tiaojietai.service`）

```ini
[Unit]
Description=Mediation Bench (training system)
After=network.target

[Service]
Type=simple
User=tiaojietai
WorkingDirectory=/opt/tiaojietai/current/src
Environment=TJ_PORT=8770
Environment=TJ_LLM_KEY=            # 密钥走 EnvironmentFile，不写在这
EnvironmentFile=-/etc/tiaojietai/env
ExecStart=/usr/bin/python3 server.py --host 127.0.0.1 --port 8770
Restart=on-failure
RestartSec=3
# 权限最小化
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/tiaojietai/current/src

[Install]
WantedBy=multi-user.target
```

## 四、容器（`deploy/Dockerfile`）

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY src/ /app/src/
RUN useradd -r -u 10001 tiaojietai && chown -R tiaojietai /app
USER tiaojietai
EXPOSE 8770
HEALTHCHECK --interval=30s --timeout=3s CMD python -c "import urllib.request;urllib.request.urlopen('http://127.0.0.1:8770/api/health',timeout=2)"
CMD ["python", "src/server.py", "--host", "0.0.0.0", "--port", "8770"]
```

## 五、nginx 反代（只追加独立 conf，不动已有站点）

```nginx
server {
    listen 443 ssl http2;
    server_name tiaojietai.example.com;

    ssl_certificate     /etc/letsencrypt/live/tiaojietai.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tiaojietai.example.com/privkey.pem;

    add_header Strict-Transport-Security "max-age=31536000" always;
    client_max_body_size 2m;

    location / {
        proxy_pass http://127.0.0.1:8770;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;      # 覆盖，防止伪造
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;   # 服务端靠它决定 Cookie 是否带 Secure
    }
}
```

## 六、日志与隐私

- 应用日志只打：时间、路径、状态码、`case_id`、维度名、分值。
- **不打**当事人姓名、不打对话原文。这条在 `docs/COMPLIANCE.md` 第 8 条，验收时要抽查。
- 登录失败计数落盘 `auth.state.json`，权限 0600，不进版本库。
