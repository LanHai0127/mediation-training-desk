# 头顶姓名牌 + 人物建模优化（v1）

> 范围：`src/web/scenes/scene3d.js`（主）、十场 `scenes/*.js` 的 `characters` 配置、
> `src/web/ui/app.js` 的转场落位、`src/web/ui/flight.js` 的缩放/俯仰夹取。
> 不动 `kit.js`、`server.py`；测试断言只在 `test_app.py` 里按新落位行为改了两处（见 §5）。

## 1. 姓名牌怎么做的

| 项 | 做法 |
|---|---|
| 载体 | `THREE.Sprite` + `CanvasTexture`（256×96 画布）。Sprite 自带 billboard，永远面向相机，**不跟人物 `rot` 走** |
| 世界尺寸 | `sprite.scale.set(0.9, 0.34, 1)`，固定世界尺寸；不做"随距离缩放" |
| 位置 | 人物组内 `y = 头顶 + 0.28m`（牌高 0.34 → 牌底离头顶 0.11m，不挡脸） |
| 底色 | `rgba(255,243,215,0.92)` 米白 + 圆角 16px + 墨色描边 `rgba(53,83,100,0.92)` 2.4px + 一道极淡内衬线 |
| 字 | `"Microsoft YaHei","PingFang SC","Hiragino Sans GB",sans-serif`；名字 31px（画布口径，约等于 15px 网页字）、身份 19px；超宽自动逐级缩字号，不出框 |
| 可交互（有 `personId`） | 左侧 9px 珊瑚色 `#e98578` 竖条（裁进圆角）+ 名字 `700` 字重，透明度 1.0 |
| 布景人物（`ambient`，无 `personId`） | 无珊瑚条 + 名字 `600`，整体透明度 **0.75** |
| 距离 | 相机到人物的**水平距离** > 18m → 淡到 **0.35**（阻尼过渡，不跳档）。用水平距离是因为俯瞰位相机高 13m，3D 距离会把整场名签提前判"远" |
| 遮挡/深度 | `depthTest: true`（被墙/家具挡住就该被挡住）、`depthWrite: false`、`renderOrder = 20`；`toneMapped: false` 保持米白不被 ACES 拉灰；`fog: false` |
| 阴影 | `castShadow = false`、`receiveShadow = false` |
| 拾取 | **可交互人物**的牌子参与射线（`userData.nameplateFor`），点牌 = 点人、直接开口（见 §4′）；布景人物的牌子 `raycast = () => {}`，不拦点击。牌子不写 `personId`，避免被并进人物包围盒 |
| 颜色空间 | `texture.colorSpace = THREE.SRGBColorSpace` |

调试口：`__mini.plates()` 返回每个人的 `{name, role, npc, opacity, base, dist}`；
`__mini.info()` 多一个 `plates` 计数（用于验收，不影响任何旧断言）。

## 2. 人物新增/重做的部件

站姿与坐姿共用一套零件（坐姿只把上身整体下移 0.20m，座面 0.57 不变）：

| 部位 | 实现 |
|---|---|
| 头 | 球体 **直接改顶点**做下颌收窄（`1 - 0.30·t^1.25`）+ 腮部外扩；**不加面** |
| 耳 | 两个压扁小球（5×4 段），轻微外旋 |
| 鼻 | 5 段小锥体，尖端朝 +z |
| 眼 | 两个深色小球 + 两个 2 面小高光片（"1px 高光"） |
| 眉 | 两条细长盒，内侧略低 |
| 嘴 | 一条薄盒，暗红 |
| 发 | 贴头皮短发帽（12×5 半球，发际线前高后低）+ 后脑一小块（8×4），默认深褐 `#3a2c22`，场景可覆盖（白发/花白） |
| 躯干 | 8 边 loft，5 圈（胯—腰—胸—肩—领口）：肩线有斜度，不再是方盒子 |
| 领口 | 一圈浅色环（open cylinder），锁骨/衣领的层次 |
| 脖子 | 8 段短圆柱 |
| 手臂 | 上臂 + 前臂两段，**肘部弯 0.22rad**；手 = 掌盒 + 拇指盒 |
| 腿 | 大腿 + 小腿两段，膝盖 0.05~0.10 微屈；鞋用圆角盒（0.095 厚，前沿圆） |
| 站姿 | 左右脚分开（-0.135 / +0.115）、一条腿略前、脚尖一外一正、上身 x 偏 0.008 —— 不再镜面对称 |
| 主角 | `makeActor` 也换成同一套人形（保留 `parts.arms/legs/knees` 关节分组，摆臂/迈腿/坐下动画不变） |

面数（每帧实测，`__mini info().tris` 与全场景 traverse 两种口径都记了）：

| 场景 | 改前全场景 | 改后全场景 | 变化 | 改前单人 | 改后单人 |
|---|---|---|---|---|---|
| duty | 16,300 | 16,412 | +0.7% | 982 / 1,086（站/坐） | **1,090** |
| wall | 67,030 | 67,246 | +0.3% | 982 | **1,090** |
| court | 38,528 | 37,764 | −2.0% | 982~1,894 | **1,090** |

每人 1,090 tri，低于 1,200 的上限；十场总面数变化 ≤ +1%（远低于 25% 的预算）。
十场每个人都是 1,090 tri（`tools/_logs/tris.json`）：duty 2 人、mediation 2、court 5、wall 2、
yard 2、lihome 1、village 3、shop 2、thresh 1、judicial 1，姓名牌数量与人数一一对应。

## 3. 缩放（A）

- 场景内 `CAM_DIST_MIN = 4`、`CAM_DIST_MAX = 36`，`CAM_PITCH_MIN = 0.12`、`CAM_PITCH_MAX = 1.48`
  （1.48 ≈ 85°，比原来的 1.35 更接近正俯视）。滚轮、双指、`setCam` 三处共用同一组常量。
- 实测滚轮档位：13 → 10 → 7 → **4**（下限）；反向 4 → 7 → 10 → 13 → 16 → 20 → 23 → 26 …
  连续、无跳变；`setCam({dist:999})` 夹到 **36**。
- 36m 在 1440×900、fov 38 下：整块 20m 底座四边都进画面并留边（截图 `ZOOM_max.png`）。
- 外壳 `flight.zoom` 同步放开到 4.0~40m（滚轮与双指同一个入口，实测拉远到 **40.0**、拉近到 **4.0**）。
- 外壳拖动改成**按俯仰角**环绕（视距固定）：落位 50° → 拖一下能到 75°，上限 **83°**（`pitch=1.45`），
  拉到 40m 时仍然能抬到 83° 看正俯视（截图 `ZOOM_shell_topdown.png`、`ZOOM_shell_far_topdown.png`）。
  旧写法按"高度米数"加、再被 4.6m 夹住，越远越抬不起来；现在 4m 和 40m 处同样手拖量 = 同样的俯仰变化。
- 缩放始终绕 `look`（视点）做，极限处只停住、不回弹。

## 4. 转场落位（B）

`app.js` 的云朵传送（`teleport → flight.transfer`）落位改成俯瞰（实测 `ZOOM_report.json`）：

- 桌面：`dist = 10m`、`height = 13m`、`lookY = 1.05` → 相机 **y = 13.01**、离主角 **16.17m**、俯角 **0.874 rad（50.1°）**；
- 竖屏手机：`dist = 13m`、`height = 14m`（水平视角窄，多退一点）；
- 落位后 `onTransfer → startPlay`：`mode = FOLLOW`、`cam = play`，自由视角照常可拖/可缩；
- 后撤没有给到 12.5m 的原因：那样人物离相机 20m+，名签会提前触发"远距离淡出"，落地第一眼看不到名字。
- 落位帧截图：`ZOOM_land_wall.png`（院墙，y=13、50°、名签可读）。

首屏（看板 → duty）的 `BOARD_VIEW 17.5 → DUTY_VIEW 9.2 → follow 4.2m` 没有改，D4/J3 的 3~5m 断言仍成立。

## 4′. 点人两条通道（2026-11 折中方案 B）

用户先要"点谁跟谁说话"，随后选了折中方案：**身体走过去（保留空间感），姓名牌原地直接聊（快速通道）**。

| 点击目标 | 主角 | 面板 |
|---|---|---|
| **身体**（`userData.personId`） | `goToPerson(id)` 寻路走过去 | 到位后场景 `fire("person:click")`，宿主开面板 |
| **姓名牌**（`userData.nameplateFor`） | 原地只转身面向对方 | 立刻 `fire("person:click")`，宿主开面板 |

- `scene3d.js`：`pickAt()` 命中时返回 `{ personId, plate: true }` 区分来源；`pointerup` / 触摸 `tapAt()`
  按来源二选一（身体 → `goToPerson`，牌 → `talkToPerson`）。两条分支都先 `clearWalk()`
  取消未完成的旧路径，避免旧目标晚一步再发一次事件、弹第二个面板。
- `talkToPerson(id)` 仍是"转身 + 立刻 fire"；`goToPerson(id)` 原样保留（走位 + 到位才发事件）。
- 姓名牌参与射线：`makeNameplate(name, role, npc, forId)` 只给可交互人物的牌子开 raycast，
  userData 挂 `nameplateFor`（不写 `personId` —— 写了会被并进人物包围盒，抬高 qa/手机探针的拾取中心）；
  布景人物的牌子仍 `raycast = () => {}`，不拦点击。
- 三条拾取链路都认这块牌子：场景 `pickAt`、触摸 `tapAt`、宿主 `pickTargetAt`（返回 `plate: true`）。
- 宿主 `startPersonTalk(partyId, {plate})`：**不调 `mini.goToPerson`**（走位由场景发起，避免走两遍、弹两次），
  只做提示 + 兜底轮询：等 `walking=false && path=0` 后若面板还没开就 `openDialog`。
  这条兜底同时覆盖"已经站在 1.5m 内、场景 walkTo 给不出路"的情况；`openDialog` 幂等保证只弹一个。

实测（`tools/_probe_talk.py`，duty 场景）：

| 操作 | 即时事件 | 2.6s 后 | 主角坐标 |
|---|---|---|---|
| 点「打电话的年轻人」**姓名牌** | `person: npc_young_man`（cursor=pointer） | 同左 | 0.9,2.6 → **0.9,2.6**（不动） |
| 点同一人的**身体** | （空：正在走） | `arrived 2.96,2.07` → `person: npc_young_man` | 0.9,2.6 → **2.96,2.07**（走位） |
| 外壳俯瞰位点李秀兰**姓名牌** | 面板打开（报案人·东院住户） | — | 0.6,5.4 → **0.6,5.4** |

截图：`TALK_plate_click.png`（俯瞰位点名牌直接开面板，主角原地）。

测试同步（旧断言 vs 新口径，不是为红改绿）：
- `qa_play.py` 7.1 文案改；**7.2 恢复 `moved > 0.3`（身体点击必须走过去）+ 只弹一个面板**；
  **新增 7.2b：点姓名牌 `moved < 0.3`、面板打开、只弹一个** → qa_play 断言数 119 → **120**。
- `test_app.py` K1 文案恢复"点身体 → 走过去 → 弹面板"（断言不变）。
- `qa_play.py` / `test_mobile.py` 的射线镜像加 `nameplateFor`：姓名牌也算"人"，
  纯地面采样不会把落在牌子上的像素当成可走的地。

`test_app.py` 两处按新行为调整并说明：
1. `F7` 从"落地后相机到主角 3~5m"改为"落地也是俯瞰位：相机离地 10~16m、离主角 ≥8m"（落位行为本身变了）；
2. `sleep(4.8) → 5.6`：转场总时长没变，但新落位让下降段更长一点，软件渲染下 F6 会卡在最后一帧（只加等待，不改断言）。

另修了一处**因俯瞰位暴露的旧竞态**：从俯瞰位点人，主角要走 9~10 米，场景的 `person:click`
和宿主"走近"轮询会各调一次 `openDialog`，第二次会把玩家刚输入的文字连气泡一起清掉。
`openDialog` 现在对"同一个人、同一模式"幂等（`dialogPartyId` + `dialogMode`）。
