# 调解台 · 3D 微缩场景提示词（v3 · 细节版）

> **v3 变更（2026-11-03）**：主题从「2.5D Canvas 地图」改成「three.js 三维微缩场景」；本版重点补**细节密度**、
> **户内装饰**与**户外景物**，并放开**非关键 NPC**（氛围人物）。旧版见 `docs/archive/`。
>
> 每条提示词都可整段复制，产出的是**能跑、能走、能点的 three.js 场景**，不是给美术的描述稿。
> 判定、对话、手机、复盘、电话这些业务层不动，只换渲染与场景表达。

## §0′ 用户对场景提示词的要求（约束级，来自历轮反馈，优先级最高）

> 这一节是**验收提示词本身的尺子**：任何新场景的提示词与产物，先过这一节再谈别的。

**一、形态与定位**

1. **3D 微缩场景，摒弃 2.5D 平面地图**——参照「海边便利店」那件成品：可拖拽、旋转、缩放观看的三维微缩底座，收藏级模型质感，三渲二卡通渲染，日式青春动画氛围。
2. **是游戏场景，不是观赏模型**——有第三人称主角，能在场景里行走；点击寻路、可交互点位、相机跟随一样不能少。
3. 场景建模由用户用自己的方式做；提示词的职责是把**内容与规格**说到可以直接生成。

**二、美感标准（以海边便利店为标杆）**

4. **细节要多**：户内装饰丰富、户外景物好看，任意一个视角都不该有空墙、空桌面、空地面。
5. **但不能堆砌**：物件的组合要合理，"通过合理的排布来体现美感"——排布语法见 §1.3（贴墙成组、间距二值化、三层纵深、视觉重量）。
6. **空旷也有空旷的美感**：晒谷场、球场中央就该空。空区看形状不看面积——像厅、像通道可以，像荒地不行；补边界，不塞杂物。
7. **有生活痕迹**：人刚离开的感觉——椅子半拉、水杯有水、烟头没掐、被褥没叠。

**三、交互（硬性）**

8. 主角能走：A* 寻路、绕开家具、不穿墙。
9. 点物件/人物/座位：**走近才触发**，不隔空。
10. **座位要能坐**：走近切坐姿，点地面起身。
11. **视角可以随意转动**：拖拽后保持，不自动回正（R 键/双击复位）。
12. 手机能玩：单指走、双指缩放、拖拽转。

**四、表现**

13. **户外的树等可加粒子效果**：落叶、飞虫、浮尘、薄雾——克制、循环、有依据。
14. 冷暖光影分层、自发光焦点（灯/屏/指示灯），画面要有视觉重心。
15. 明令禁止：悬浮的灯、墙上重叠的物件、场景内 UI、真实警徽/单位/品牌、乱码、水印。

**五、内容与人物**

16. **每个场景出现什么要合理**：物件要能答出"为什么在这"；证据必须落在与剧情对应的场景。
17. **可以有非关键 NPC（氛围人物）**：不抢戏、不挡路、不响应对话，动物也算——比人多更有生活气。
18. 关键人物（当事人/证人）可交互；证人是"证据的活载体"，位置与证词场景对应。

**六、分工与验收**

19. 业务层（判定/对话/手机/复盘/电话）与渲染无关，只换场景层。
20. 每个场景产物按 §7 验收过一遍（20 条），再谈接进训练台。

| 项 | 规格 |
|---|---|

## §1 通用系统段（每个场景先粘这段）

```
你是一名 three.js 场景工程师，请产出一个可直接运行的三维微缩场景，风格为三渲二卡通风。
这不是观赏模型，是一个能操控主角在里面走动的游戏场景。

【技术约束，逐条遵守】
1. three@0.180，ES module；PerspectiveCamera(fov 38)。
   相机二选一：
   （a）纯观赏用 OrbitControls（damping、enablePan=false、极角 10°~80°、距离 8~30）；
   （b）**游戏场景推荐自研相机**：azimuth/pitch/distance 三个量 + 目标点跟随角色，
       因为 OrbitControls 的 target 是静态点，跟人走要每帧手改，容易和"拖拽"打架。
   无论哪种：**不要做"松手自动回正"**，视角由用户掌握；R 键或双击复位。
2. 全部程序化几何（Box / Cylinder / Sphere / Plane / Torus / Cone），不加载任何外部模型或贴图；
   文字、招牌、海报用 canvas 画好后作贴图。
3. 材质统一 MeshToonMaterial（三渲二），低饱和。玻璃透明（opacity 0.35~0.6，depthWrite:false）；
   **有积水/沟水的场景**用两层半透明叠色 + `texture.offset` 缓慢位移（别用折射，代价太高）；
   金属给一点 specular 感，别做成镜面。MeshToonMaterial 想出台阶感可传 3 阶 gradientMap，不传则柔和。
4. 光照：暖主光（DirectionalLight，投阴影，shadow map 2048）+ 冷补光 + 半球光；
   ACESFilmicToneMapping，曝光 0.9~1.0；光比要软，阴影不死黑。
5. FogExp2（密度 0.006~0.01），让远景收进底座。
6. 底座：20×20、厚 0.55，侧面深一号；底座外什么都不放。
7. 单场景 5~12 万三角面；动画只做"循环的、克制的"微动，clock 驱动，不引第三方库。
8. 没有任何 UI：无按钮、无面板、无 loading 文字、无坐标轴、无调试网格、无水印。
9. 代码组织：box/cyl/sph/plane/label 几个辅助函数压重复；动画收进一个 animated 收集器。
10. 交付完整文件，我复制就能跑。

【可玩性，优先级最高——没有它这个场景就是废的】
A. 必须有一个玩家可操控的主角（第三人称），能在地面行走。
B. 点地面 → 沿 A* 走过去（绕开家具，不穿墙）。
C. 点物件/人物 → 走到交互距离（2.2 单位）后**才**触发，不隔空触发。
D. 可交互物件要有热区，hover 轻微提亮；不可交互的东西不许做成"可点"。
E. 相机跟随主角（死区 3 单位）；拖拽可自由绕看，**松手后不自动回正**（R 键/双击才复位）。
F. 手机能玩：单指点击移动、双指缩放、拖拽旋转。

【美术总则】
- 干净、通透、有生活气；哑光塑料 + 少量玻璃与金属反光，像"涂装好的树脂模型"。
- 每场景一个主色 + 一个对比色 + 中性灰白；不要满屏高饱和。
- 光比要软：主光 1.6~2.6，补光 0.8~1.3，环境 0.4~0.6。
- **细节要多、但不能乱**：一个视觉中心、两三个次中心，其余都往后退（降饱和、压对比）。
- **排布优先于数量**：先把主通道、视觉中心、主墙定下来，再沿墙成组摆；摆完再数件数。
```

## §1.2 可玩性规格

### 一、主角与移动

| 项 | 规格 |
|---|---|
| 表示 | 一个 Group：躯干 + 头 + 四肢；脚底 origin 在 (0,0,0)，Y 贴地 |
| 站立 | 高 1.7；行走时上下起伏 0.04，摆臂 ±0.5 rad |
| 输入 | 左键/单指点地面 → 目标点；点人物/物件 → 该物体的交互点 |
| 寻路 | 0.5 单位网格（约 37×37，覆盖 [-9.2, 9.2]），A* 八向，斜走要求两正交格都通；**结果要拉直**（共线合并 + 视线检测） |
| 碰撞 | 障碍登记 AABB（x,z,w,d），膨胀 **0.3~0.35** 后标不可走。**膨胀必须小于半格**——用 0.45 会把两件相邻家具之间的通道彻底堵死 |
| 移动 | 速度 2.6~3.4 单位/秒；朝向按速度方向平滑旋转（每帧 ≤8°） |
| 到达 | 距目标 < 0.15 判定到达，清空路径并回调 `actor:arrived` |
| 卡住 | 目标在障碍内 → 吸附最近可走格；无路 → 不动 + 回调 `actor:blocked` |

### 二、交互

| 项 | 规格 |
|---|---|
| 拾取 | Raycaster 对 pickable 组命中；人物用放宽的球形热区（0.6） |
| 走近 | 命中后先送主角到 `interactPoint`，到位才触发 |
| 距离 | 交互距离 2.2；超出只走位，不触发 |
| 反馈 | hover：把材质 `emissive` 设成暗色（如 `#223344`），离开时置黑；选中：脚下 0.5 半径半透明圆环 |
| 座位 | 椅子/长椅/沙发带 `seat: true` + `interact` 落点：走近后切坐姿（腿弯、整体下沉 0.3），点地面自动起身 |
| 事件 | 回调 `spot:click {id}` / `person:click {id}`；不在场景里弹文字 |

### 三、相机

| 项 | 规格 |
|---|---|
| 初始 | 距离 24，仰角 36°，方位角 45°，目标 = 主角 + (0, 0.9, 0) |
| 跟随 | 目标点 lerp 0.08；死区 3 单位（站着不动时画面不抖） |
| 手动 | 拖拽绕主角旋转；滚轮/双指改距离 8~30 |
| **不回正** | 松手即保持当前视角；R 键 / 双击复位到初始机位 |
| 限制 | 相机不得低于地面 1.2，避免钻进地板 |

## §1.3 排布：美感来自秩序，不是件数

> 先说结论：**空房间堆满东西只会变乱，不会变美。**
> 便利店好看，是因为它有清楚的秩序——货架等距、招牌居中、动线明确、前景有遮挡。
> 件数只是结果。这一节给的是"怎么摆"，不是"摆多少"。

### 一、三条排布语法（照做就不会乱）

**① 贴墙成组，中央留通道**
家具沿墙排，同类成组（柜子挨柜子、椅子挨椅子），间距 **≤0.2**；
组与组之间留 **≥1.2** 的通道。**不允许所有间距都在 0.6 左右**——那是"随手摆"的典型特征。

**② 间距二值化**
任意两件家具的距离，要么"挨着"（<0.2），要么"能走人"（>1.2）。
中间值只留给"故意要分开的两组"，且要有理由（比如桌与墙之间留 0.8 给拉椅子）。

**③ 三层纵深，每层都要有东西**
| 层 | 位置 | 作用 | 例子 |
|---|---|---|---|
| 前景 | 画面下缘 1/4 | 制造遮挡，挡一点视线才像"真的在屋里" | 半张桌子、椅背、绿植、门框 |
| 中景 | 画面中部 | 主体，主角在这里活动 | 值班台、调解桌、沙发组 |
| 背景 | 贴墙 | 压住画面，别让墙空着 | 柜、公示栏、窗、挂件 |

视线从相机到主体之间**必须有一件东西**（哪怕只是一把椅背）——没有遮挡，画面就是"俯视平面图"。

### 二、空间分区（每个场景先画一张 zone 表）

动笔前先定三件事：**主通道从哪进、往哪走；视觉中心在哪；哪面墙是主墙。**

| 场景 | 主通道 | 视觉中心 | 主墙（挂东西的那面） |
|---|---|---|---|
| S0 值班室 | 门厅 → 取号 → 值班台前 | L 形值班台 | 后墙（白板 + 挂钟 + 海报） |
| S1 调解室 | 门 → 桌侧 → 记录席 | 调解桌 | 后墙（窗 + 流程牌） |
| S2 篮球场 | 人行道 → 场边 → 半场 | 篮架 + 罚球区 | 围网侧 |
| S3 院墙地界 | 土路 → 墙根 → 沟 | 新旧砖色分界 + 界石 | 院墙本身 |
| S4 张家院 | 院门 → 方桌 → 堂屋 | 方桌（权证） | 堂屋门前 |
| S5 李家院 | 栅栏 → 堂屋门口 → 桌 | 屋檐排水口 + 单据 | 堂屋桌 |
| S6 村部 | 大门 → 长桌 → 档案柜 | 翻开的账册 | 规划图那面墙 |
| S7 小卖部 | 街面 → 台阶 → 长凳 | 长凳（王彩凤） | 柜台 + 价目表 |
| S8 晒谷场 | 场边 → 树下 → 通知栏 | 树下诊箱 | 通知栏（四面围合，中央刻意空） |
| S9 司法所 | 大门 → 柜台前 → 卷宗室 | 柜台 + 标识牌 | 标识牌那面墙 |

主通道上**不许放任何东西**（包括盆栽、纸箱）。绕行会让"这是个能走的地方"这件事立刻垮掉。

### 三、对齐与边距（最容易出效果的一条）

- 同一面墙的家具，**背线对齐**（都贴到距墙 0.05），不要一件贴墙一件离墙 0.4；
- 挂墙件**水平居中对齐**到它下方的家具（公示栏对着长椅、画对着柜）；
- 边距统一：家具到墙 0.05，挂件底边离地 1.4~1.6，桌面小物距桌沿 ≥0.08；
- 同族物件**等距重复**（三连椅、两排货架、一列海报），重复本身就是秩序感。

### 四、视觉重量

| 类型 | 体量（世界单位） | 该放哪 |
|---|---|---|
| 重 | 高 > 1.6 或占地 > 1.2 | 贴墙、靠角，别放中央 |
| 中 | 0.8~1.6 | 中景，成组 |
| 轻 | < 0.8 | 前景与桌面，用来"破"直线 |

一张画面里"重"的不超过 4 件，否则压得慌；"轻"的要散开，全堆一处就乱。

### 五、留白不是空，是"被框住的空"

- **空区不设面积上限**：空旷本身可以是设计——大厅、院子、球场都要空才成立，硬塞东西反而坏。
  要保证的是**有形状、有边界**：要么被家具围合（三面有物），要么是一条有起终点的通道。
- 判断标准从"占多少"换成"像什么"：
  · **像厅**（被家具围合的矩形空地）→ 可以，越大越要有中心物或地面分格；
  · **像通道**（两侧有物、宽度一致 1.2~1.5）→ 最好；
  · **像荒地**（四边都没有依托、形状不规则）→ 不行，补边界，不要补杂物。
- 空旷要"透气"：留一块完整空面 + 一处地面材质变化（地砖分格、地毯、水磨石拼花），比摆十件东西有效。

### 六、自检：截四张图，逐张过

1. **看空区形状**：中央那块空地，是"被家具围出来的厅/通道"，还是"四边没依托的荒地"？
   是荒地就补边界（矮柜、绿植、地面分格），**不要靠塞杂物填**。
2. **看贴墙率**：四面墙，每面墙 0.5 米内都有东西吗？空的墙面 = 没做完。
3. **量间距**：随便挑三对家具，间距是不是都在 0.5~0.9 之间？是的话重排。
4. **找遮挡**：从相机看主体，中间有没有一件前景物？没有就加一把椅背/一盆植物。
5. **转 90°**：每转一次截一张，四个方向都不能出现"一面空墙 + 一片空地的组合"。
6. **眯眼测试**：把图缩小到 1/4，看是否有明确的明暗块面；如果是一片糊，说明主次没拉开。

### 七、密度只作参考（不要为了凑数而摆）

| 类型 | 参考件数 | 说明 |
|---|---|---|
| 室内 | 35~55 件 | 低于 35 基本是空屋；高于 55 通常是重复堆砌 |
| 室外 | 28~45 件 + 6 处环境细节 | 树、灯、杆这些大件少，小件多 |

**件数达标但排布散 = 不及格；件数略少但成组对齐 = 合格。**

### 八、六个层次的检查表（每层都要有"节奏"，不是"有东西"）

| 层 | 节奏怎么来 |
|---|---|
| 结构 | 地面材质分格、墙裙一条通到底、吊顶带与墙对齐 |
| 家具 | 沿墙成组，组内间距 <0.2，组间 >1.2 |
| 桌面 | 3~5 件一组，沿桌沿排，留出一块空台面给"操作" |
| 墙面 | 主墙一件大的 + 两侧各一件小的，水平居中 |
| 角落 | 1~2 件（扫把/纸箱/盆栽），别超过三件 |
| 环境 | 光斑、浮尘、水渍、磨损——点缀，不起眼但少了就假 |

## §2 场景创作提示词（十个，对应三案）

> 每条可整段复制，前面拼 §1。
> **顺序：先按 §1.3 定主通道 / 视觉中心 / 主墙 → 再沿墙成组摆 → 最后补桌面与角落。**

### 4.3 氛围人物（非关键 NPC，不可交互）

> 目的：让场景"有人住过"。但他们**绝对不能抢戏**，也不能挡路。

| 规定 | 说明 |
|---|---|
| 数量 | 每场景 1~3 个；室内 1 个、室外 2~3 个 |
| 交互 | **不注册进 pickable**；点他们等同点地面（人走过去），不触发任何对话 |
| 姿态 | 只做 1~2 个微动（呼吸、低头看手机、抽烟的手、尾巴摇），不做位移 |
| 位置 | 放在边缘或背景层，距主通路 ≥ 2 单位；不站在门口/桌前等关键路径上 |
| 颜色 | 比关键人物低饱和 15~20%，不与主角色撞色 |
| 尺寸 | 与关键人物一致，不缩小（缩小会显得像摆件） |
| 名单 | S0 抱布袋的老太太、走廊口打电话的年轻人；S1 门口抱文件袋的中年男；S2 场边压腿的老人、骑车的学生、抱孩子的年轻妈妈；S3 无（两人已是关键人物）；S4 无（张守义在场）；S5 无（李秀兰在场）；S6 一个来打证明的村民；S7 无（王彩凤在场）；S8 场边两只麻雀（动物）；S9 一位来咨询的老人 |
| 动物 | 允许（S3 院里的鸡、S6 窗外的狗、S8 场边麻雀）——它们比人更能表现"生活气" |

## §5 动效清单（克制、循环）

| 类 | 做法 | 幅度 |
|---|---|---|
| 灯 | 点光强度正弦微调 | ±2% |
| 风 | 树叶、电线、海报边角、窗帘、晾衣 | 摆角 ≤ 3° |
| 水 | 水面 UV 偏移；浪花/积水用半透明片往返 | 周期 6~9 秒 |
| 滴落 | 屋檐/龙头：小球下落 → 涟漪圆环扩散 | 3 秒一次 |
| 机械 | 风扇、秒针、指示灯、猫呼吸、鸡啄食 | 各自固定节奏 |
| 雾 | 贴地薄雾片缓移 | ≤ 0.02 单位/秒 |
| 粒子 | `THREE.Points`：一组随机点 + 每帧 y += dt*k，超出高度回到底部；大小 0.02~0.04，透明度 0.4~0.6，`depthWrite:false` | 上浮 0.05 单位/秒 |

**描边怎么做**（不用后处理）：复制一份 mesh，材质改 `MeshBasicMaterial({ color: 深一号, side: THREE.BackSide })`，
缩放 1.01~1.02，只给主要家具（桌、柜、门、椅）做，别全场景做——面数会翻倍。

**自发光怎么做**：灯管、屏幕、指示灯用 `MeshToonMaterial({ emissive: '#ffdca8', emissiveIntensity: 1.2~1.6 })`。
冷环境里有几个亮点，画面才有焦点——但整场景不要超过 4 处，否则夜景会糊。

**禁止**：粒子爆炸、镜头摇晃、色温突变、随机闪烁（会被当成 bug）。

## §6 与训练台的接入

```
┌─────────────────────────────┐
│ 训练台页面（现有）           │  方案区 / 对话坞 / 卷宗 / 手机 / 复盘
│  ┌───────────────────────┐  │
│  │  <iframe> 3D 场景页    │  │  three.js 微缩场景
│  └───────────────────────┘  │
└─────────────────────────────┘
        ↕ postMessage 事件桥
```

| 方向 | 消息 | 载荷 | 实现状态 |
|---|---|---|---|
| 页面 → 场景 | `actor:move` | `{x, z}` | ✅ 已实现 |
| 页面 → 场景 | `actor:teleport` | `{x, z}` | ✅ 已实现 |
| 页面 → 场景 | `spot:goto` | `{id}` | ✅ 已实现（走近某物件） |
| 页面 → 场景 | `scene:load` | `{caseId, sceneId, characters:[...]}` | ⬜ 未实现：场景数据在场景侧，切换用 URL 参数（`?scene=duty`） |
| 页面 → 场景 | `spot:highlight` | `{ids:[]}` | ⬜ 未实现（预留） |
| 场景 → 页面 | `scene:ready` | `{}` | ✅ 已实现 |
| 场景 → 页面 | `actor:arrived` | `{x, z}` | ✅ 已实现 |
| 场景 → 页面 | `actor:seat` | `{id}` | ✅ 已实现 |
| 场景 → 页面 | `actor:blocked` | `{}` | ✅ 已实现 |
| 场景 → 页面 | `spot:click` / `person:click` | `{id}` | ✅ 已实现 |

> 所有消息统一带 `{ source: "mini3d", type, payload }` 外壳。父页面必须先校验
> `ev.origin === location.origin` 且 `ev.data.source === "mini3d"` 再处理——iframe 里可能被别的脚本注入。

> ⚠ **CSP 坑（已踩）**：现有页面 CSP 是 `script-src 'self'`，**内联脚本会被直接拦掉**。
> 场景脚本必须外链（`<script type="module" src="./duty.js">`），否则页面一片空白，
> 控制台只有一行 CSP 拒绝，很容易误判成"three 加载失败"。iframe 方案需单独放行 `frame-src`。

## §7 验收

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 双击/直链能开，无外部请求 | 断网打开，控制台无 404 |
| 2 | 能 360° 旋转、缩放、不平移出画面 | 拖一圈，底座始终在画面里 |
| 3 | 无悬空物件 | 转到侧面看，所有东西都落在底座上 |
| 4 | 60fps 桌面 / 30fps 手机 | 性能面板 + 真机 |
| 5 | 画面里无 UI | 截图肉眼看 |
| 6 | 三角面 ≤ 12 万、单文件 ≤ 1.2MB | `renderer.info` + 文件大小 |
| 7 | 冷暖分明、主体不糊 | 截图对照色调 |
| 8 | 动效克制 | 静看 10 秒，没有跳变 |
| 9 | **能走** | 点桌子另一侧，人绕过去而不是穿过去 |
| 10 | **走近才触发** | 隔半场点人物，事件不应立刻触发 |
| 11 | **不卡死** | 连点十几个点，人都能回来 |
| 12 | **视角保持**：拖到任意角度，松手 2 秒后仍停在那儿 | 拖到侧面等 2 秒，画面不许自己转回去 |
| 13 | **细节量在参考区间**（不是硬指标） | 室内 35~55、室外 28~45；低于下限是空屋，高于上限多是重复堆砌 |
| 14 | **没有"整面空墙"**（地面与中央可以空，墙不行） | 每隔 90° 截一张，逐张看墙 |
| 15 | 氛围人物不挡路、不响应点击 | 点他们只会走过去 |
| 16 | **排布**：空区"像厅"或"像通道"，不是"像荒地" | 俯视截图判形状，不量面积 |
| 17 | **贴墙率**：每面墙 0.5m 内都有物件 | 四面墙逐个看，不许有整面空墙 |
| 18 | **间距二值化**：没有"所有间距都在 0.6 左右"的散摆 | 挑三对家具量一下 |
| 19 | **前景遮挡**：相机到主体之间至少有一件物 | 顺着视线找，没有就加椅背/绿植 |
| 20 | **眯眼测试**：缩到 1/4 仍有明确块面 | 截图缩小看 |
