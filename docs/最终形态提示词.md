# 调解台 · 最终形态提示词（v1 · 体验层）

> 这份是**产品最终形态**的施工依据，不是设计散文。
> 前三份（`场景与人物建模提示词`、`提示词审查`、本文件）各管一层：
> **场景层**管"每块地台好不好看"，**体验层**（本文件）管"人进来之后经历什么"。
> 写这份之前已经定下的事实：十场 3D 微缩场景已建、手机功能在国庆项目里跑通过、
> 案子数据结构（`case.json`）已有 `spots / characters / evidence / rubric`。

## §0 体验总纲：把十个"模型"接成一部能操作的动画电影

现在的状态是：**十个各自能转着看的盒子**。玩家从哪进、怎么进、进去干什么、出来怎么评，全是空的。

这一版要补的就是这条主线，一句话概括：

> **主界面是一块悬在值班室上空的浮空看板 → 点开始 → 镜头俯冲落到民警身上 →
> 用手机调档/看证据/打电话/传送 → 在场景里走、问、看、坐 → 出方案 →
> 一份调解评价 + 一次复盘回放。**

三条不可动摇的约束：

1. **3D 场景是唯一舞台**。不要再出现 2.5D 画布；交互一律是"点场景里的东西"或"走近它"。
2. **运镜是唯一的转场语言**。没有黑场、没有淡入淡出的白屏（云朵转场是唯一的例外，且必须是云的形状），
   没有 loading 文字，没有跳页刷新。
3. **手机是唯一的功能入口**。所有非场景交互（档案、证据、法条、地图、学习、评价、复盘）都在手机里，
   永远不铺满屏幕，永远从右侧滑入、占屏 38%。

## §1 第一屏：浮空看板（参考明日方舟主界面）

### 1.1 画面构成

- **背景就是 S0 值班室本体**，不是插图。相机悬在房间上方 **8.5 米**、俯角 **32°**、
  以 **0.06 弧度/秒** 极缓环绕——玩家一进来就看得见"里面是真的屋子"。
- 房顶的灯全部亮着，窗外是上午的光；房间里的物件全部是场景里那一套（不是另画的图）。
- **四块浮空看板**悬在房间上空，尺寸 **3.2 × 1.8 × 0.08**（世界单位），
  奶油白底板 + 墨色描边（`#355364`，1.5px）+ 一条珊瑚色下划线。
  内容分别是：
  - **主看板**（居中最高，y=5.6）：标题「调解台」+ 副标「基层矛盾纠纷调解训练」
  - **开始游戏**（左，y=4.9）：一行主按钮，悬停时下方出现 0.06 高的暖黄光条
  - **案件选择**（右，y=4.9）：「院墙案 · 广场舞案」两枚案件章
  - **学习**（下，y=4.2）：「先学怎么用，再学怎么调」
- 四块看板朝向相机，随相机环绕做 **0.6 / 0.9 / 1.2 的深度错位**（近的略微放大、远处略微减小），
  营造"悬在空气里"的层次。

### 1.2 鼠标视差（这是第一印象，必须做对）

- 鼠标在屏幕上的位置映射到相机 **yaw ±0.35 弧度 / pitch ±0.18 弧度**，
  跟随阻尼 **0.08**（不是硬跟，要有"镜头被轻轻推动"的手感）。
- 看板组再叠加一层 **0.4 倍的二级视差**（比相机慢半拍），制造纵深。
- 鼠标静止 3 秒后，视差缓慢回正（0.02 弧度/秒）。
- **禁止**：鼠标一动看板就整块平移（那是最廉价的假 3D）；禁止视差幅度超过 0.4 弧度（会晕）。

### 1.3 从看板到场景（开场运镜）

点「开始游戏」后 **2.4 秒**的运镜，分三段：

| 段 | 时长 | 相机 | 画面 |
|---|---|---|---|
| 起 | 0.35s | 原地轻微后拉 0.6m | 看板同时向外散开、透明度 1→0，主看板碎裂成 24 片（每片 0.12×0.12，带描边）沿抛物线落下并在 1.2s 内淡出 |
| 落 | 1.65s | 沿贝塞尔曲线从 (0,8.5,-6) 落到主角背后 (x, 1.6, z+2.6)，FOV 38→42 | 穿过房间上空，桌面上那台显示器/对讲机的细节从模糊变清楚 |
| 定 | 0.4s | 缓动 easeOutCubic 停稳，yaw 对准主角朝向 | 主角轻微转身，抬手机看一下又放下（一个 0.8s 的动作） |

缓动统一用 `easeInOutCubic`；整个运镜期间禁止玩家操作（点击可跳过，跳到"定"段末尾）。

## §2 相机系统（一张状态机表，所有运镜都走它）

| 状态 | 位置 | 看向 | 玩家可操作 | 进入方式 |
|---|---|---|---|---|
| `BOARD` | 场景上方 (0, 8.5, -6)，环绕 | (0, 1.2, 0) | 鼠标视差 | 启动 / 从场景返回 |
| `FOLLOW` | 主角背后 2.6m、高 1.6 | 主角前方 1.2m | 拖拽环绕 ±60°、滚轮 1.6~6m | 开场运镜结束 / 关手机 |
| `DIALOG` | 双方中点侧移 2.2m、高 1.5 | 当前说话人 | 禁止 | 与人物对话 |
| `LOOK` | 目标物正前 1.2m、高 1.3 | 物件中心 | 禁止（可拖 15°） | 查看证据 |
| `FLIGHT` | 由转场脚本控制 | 脚本控制 | 禁止（可跳过） | 地图传送 |
| `REPLAY` | 场景上方 45°、高 7m | 场景中心 | 自由环绕 | 复盘 |

规则：
- 任何状态切换都必须有 **≥0.6 秒的缓动**，禁止硬切。
- `FOLLOW` 状态下相机永远不穿墙、不穿家具（用射线检测，撞到就沿墙滑）。
- `DIALOG` 的机位要在两人连线的**垂直方向**偏移，不能正对任何一方（正反打会晕）。
- 所有可操作状态都支持"双击画面回正"（回到默认机位，0.5 秒）。

## §3 云朵转场（地图传送）

这是全作唯一允许的"全屏遮挡"，必须做成**一朵云压过来**，而不是白屏。

```
0.0s  升空：相机在 1.8s 内升到当前场景上方 14m，俯角拉到 90°（正俯视）
1.8s  云起：6 团云从画面四边合拢，每团是一张带柔和描边的圆润云形（奶油白 + 0.08 的墨边），
      先在远处小、再迅速变大盖满；云团各自有 0.06 的漂浮摆动
2.6s  遮实：全屏被云盖住（不是纯白，要有 0.9 透明度的云纹理，能隐约看见一点点亮）
3.0s  切换：场景在云后换掉（0.1s，玩家看不见）
3.1s  云散：云从中心向四周散开，1.2s 内露出新场景
4.3s  落地：相机从新场景上方 14m 落到主角背后，1.6s
5.9s  完成
```

- 全程 **5.9 秒**，任意时刻点击可跳过（跳到 5.9s）。
- 云的形状用**同一个云形剪影**的 5 个变体，不要用照片云。
- 传送期间手机收起；落地后手机重新出现，地图页自动切到新地点。

## §4 手机系统（唯一功能入口）

### 4.1 外观与进出

- 手机壳 **0.62 × 1.2**（占屏高 62%），深蓝灰机身 + 1px 描边 + 圆角 0.12，右侧滑入 **0.35s**。
- 展开时背景场景**模糊 6px、压暗 22%**（不是遮死，要能看见后面还在动）。
- 九宫格图标 3×3，每个 0.62×0.62，图标下方 0.5 行小字标签。
- 点空白处或再点手机图标收起。

### 4.2 九个功能

| # | 功能 | 内容 | 数据来源 |
|---|---|---|---|
| 1 | **案件档案** | 当事人、诉求、争议焦点、受理情况 | `case.json` |
| 2 | **人物关系** | 关系图（节点 + 连线），点节点看简介 | `characters` |
| 3 | **证据夹** | 已收集证据卡片，未收集的是灰色问号 | `evidence` |
| 4 | **笔记** | 玩家自己记的要点，支持随手便签 | localStorage |
| 5 | **法条** | 民法典相邻关系、调解程序、司法确认 | `laws.json` |
| 6 | **地图** | 本场景平面 + 可传送地点；点地点=云朵转场 | `scenes[].spots` |
| 7 | **通讯** | 打电话（找支书、找司法所、找村里老人） | `case.json` |
| 8 | **学习** | **两个 Tab：操作 / 知识**（原教程改） | 见 §7 |
| 9 | **评价 / 复盘** | 结案后解锁；未结案时灰掉，点它提示"案子还没结" | 见 §6 |

### 4.3 地图页的特殊规则

- 只显示**当前案子涉及的地点**（院墙案 6 处、广场舞案 4 处），没去过的是虚线轮廓。
- 传送到"没去过"的地点要额外 0.4s 的云，并在落地时给一句环境提示（"这儿就是李家的院子"）。
- **不能传送到当前所在地点**（点了抖一下并提示）。

## §5 3D 场景内交互（替换掉旧的 2.5D 点击区）

| 操作 | 触发 | 反馈 | 结果 |
|---|---|---|---|
| 点地面 | 点空地 | 落点出现一个 0.9 半径的光环，0.4s 扩散消失 | 主角走过去 |
| 点物件 | 点有交互的家具 | 物件描边变亮 + 抬头 0.12 | 走到 2.2m 内触发 `spot` |
| 点人物 | 点人 | 人物转向主角 + 描边 | 走到 2.6m 内触发 `person`，进入 `DIALOG` |
| 走近自动触发 | 距离 ≤2.2m | 物件轻微发光 | 同"点物件" |
| 坐下 | 点带 `seat` 的家具 | — | 主角坐下，视角切到侧后方 |

- **高亮只加描边，不改颜色**（改颜色会破坏色板）。
- 没交互的家具：点它 = 走到它前面站住（不要什么都不发生）。
- 移动端：单击=点击，拖动=转视角，双指=缩放。

## §6 调解评价机制（新增，本作的核心产出）

结案或谈崩后，**先出评价，再出复盘**。评价分三个维度，各自独立打分：

### 6.1 了解度（0~40）

```
了解度 = 已查看的关键证据权重和 / 全部关键证据权重和 × 40
```
- 每件证据有 `weight`（关键 2、一般 1、干扰 0.5）。
- 只"看过"不算，**必须触发过 spot 或 person 才算**（点一下就跑开不算）。
- 低于 60% 触发一句提示："你还没弄清排水沟到底是从哪一年堵的。"

### 6.2 方案合法合规（0~35）

- 把玩家的方案拆成"主张"（每句话一个主张），逐条匹配法条库：
  - 命中且引用正确：+分值；只给结论不给依据：半分；**引用错法条**：−3
- 三个必答点各占 8 分：①是否指出"排水沟属于历史形成的共用排水" ②是否给出"不得擅自堵截"的结论
  ③是否提出"费用分摊"或"恢复原状"的具体方案
- 剩下 11 分给"有没有写清履行方式和期限"。

### 6.3 可执行性（0~25）

- 有时间（3 天内/7 天内）+8；有违约责任或司法确认指引 +7；双方都留了可接受的理由 +10。
- **一方完全没让步**且方案里没解释原因：扣 8。

### 6.4 输出卡片

一张竖版评价卡（宽 5.2、高 6.4 世界单位，浮在场景上方，可旋转查看）：

```
调解评价        81 / 100        B（良好）

你做得对的
· 你抓住了排水沟断头这个关键，也问到了三十年前那桩旧事
· 你给了"七天内清通"的具体期限

你漏掉的
· 张家的收货台账（能证明他确实靠这条路运货）
· 李家屋檐没有滴水槽这件事，你没往"排水侵权"上引

哪条不合规
· "让他自己拆了就行" —— 这句话没有法律依据，相邻排水不能单方处置

下一轮建议
· 先分别听，再合起来谈；把"共同出资清通"作为第一方案提出来
```

字色只用墨色与珊瑚色两种；分数用大字，评级用一枚圆形印章（A/B/C 三档）。

## §7 复盘系统

- **时间轴**：从第一句对话到结案，抽出 **10~14 个关键节点**（每个节点记：时间、地点、玩家动作、结果）。
- 点节点 → 相机在 `REPLAY` 状态下**飞回当时的机位**，场景里回放那 30 秒（其余人变半透明）。
- 每个节点右侧给"如果当时…"的对照（一句，不超过 30 字）。
- 底部一条进度带：绿=做对、黄=可更好、红=明显失误，一眼看出整场走势。

## §8 学习系统（原"教程"改）

两个 Tab，都不出手机：

**操作**（8 条）：怎么走、怎么点物件、怎么看证据、怎么问人、怎么开手机、怎么传送、怎么写方案、怎么提交。
每条 = 一个 3 秒的 3D 小演示（复用真实场景，只是换机位）+ 两行说明。

**知识**（12 张卡）：调解的受理范围 / 回避 / 背靠背 / 面对面 / 相邻排水 / 宅基地边界 /
口头协议的效力 / 履行与司法确认 / 证据固定 / 情绪降温 / 记录要点 / 结案文书。
每张卡：一个核心结论（≤20 字）+ 三行解释 + 一条法条出处。

### 10.2 场景页与外壳的契约

场景页（`scenes/*.html`）保持现在的接口不变，只多两件事：

```js
// 外壳 → 场景
{ source: "host", type: "scene:enter", payload: { caseId, camera: "land" } }
{ source: "host", type: "phone:open" | "phone:close" }
// 场景 → 外壳
{ source: "mini3d", type: "scene:ready", payload: {} }
{ source: "mini3d", type: "spot",   payload: { id, weight } }
{ source: "mini3d", type: "person", payload: { id } }
{ source: "mini3d", type: "seat",   payload: { id } }
{ source: "mini3d", type: "ask",    payload: { personId, topicId } }   // 对话抽屉
```

## §11 验收

### A. 机器可测

| # | 判据 |
|---|---|
| A1 | 首屏 3 秒内出现浮空看板，鼠标移动相机 yaw 变化 ≥0.1 弧度 |
| A2 | 点"开始游戏"后 2.4±0.3s 相机进入 `FOLLOW`，且主角在画面中心 1/3 内 |
| A3 | 地图传送全程 5.9±0.4s，中途有 ≥0.6s 的全屏云遮挡 |
| A4 | 手机打开 0.35s 内可达，占屏宽 38%±3%，九个图标全部可点 |
| A5 | 走遍所有证据点后，了解度 = 40（满） |
| A6 | 提交方案后 2s 内出评价卡，三个维度分数之和 = 总分 |
| A7 | 复盘时间轴节点数 10~14，点任一节点相机飞回且回放可播 |
| A8 | 十场场景在 `FOLLOW` 下都不穿墙、不卡住 |

### B. 肉眼判

| # | 判据 |
|---|---|
| B1 | 首屏像"游戏主界面"，不像"模型预览器" |
| B2 | 运镜有起承转合，不晕、不跳、不硬切 |
| B3 | 云朵转场看得出是云，不是白屏 |
| B4 | 手机是"工具"不是"网页"：不铺满、不滚动条、不换页 |
| B5 | 评价卡读起来像一份真实的点评，不像自动生成的分数 |
| B6 | 复盘能让人"哦，原来当时该这么问" |
