## 四、完整体验层（一条线）

1. **首屏**：浮空看板「开始调解」，鼠标移动有视差。
2. **加载**：十场逐个预热，进度条 + 十个圆点；不到 100% 不进场景。
3. **开场运镜**：云散后相机从俯瞰位下移到常规位，再把镜头交给玩家。
4. **手机**：右上角图标滑出；九宫格 = 案件 / 人物 / 证据 / 笔记 / 法条 / 地图 / 通讯 / 学习 / 评价复盘。
5. **场景内交互**：点地面走人、按住拖动转视角、滚轮缩放、走近物件才触发证据、点人物走近才开口。
6. **问话面板**：按人物身份定制的 4~6 条话题；单独谈 / 面对面；信任与情绪两条量表；越界承诺提醒；单独谈且信任够时吐隐情。
7. **评价卡**：了解度 40 + 合法合规 35 + 可执行性 25，总分、评级、四段点评。
8. **复盘**：10~14 个真实操作节点的时间轴，点节点相机飞回，可回放。

## 五、问话内容层（2026-11-05）

- **8 位当事人、44 条定制话题**，每人 4~6 条；问法按身份写（问当事人 / 问村干部 / 问物业 / 问证人，口气完全不同），回答也是按话题写的定制回话。
- 数据全部落在 `src/web/cases_dialog.json`：`cases.<cid>.parties.<pid>.topics[]`，每条带 `"authored": true`；旧的 `topics` 五条通用动作只作兜底，旧的 `answers` 逐字保留作最后回退。
- 渲染与请求在 `src/web/ui/dialog.js`：**回答优先 `POST /api/dialogue`**；离线 / 降级时回退到话题自带的 `answers`（仍在 json 里），再退案卷 `answers`。**js 里不写死任何一句台词。**
- 法条提示只在数据文件里，引用到具体条号：`《民法典》第二百八十八条 / 第二百八十九条 / 第二百九十条 / 第二百九十四条`、`《人民调解法》第三条 / 第二十三条`、`《消防法》第二十八条`；不确定的写"参见相关规定"。

## 八、边界与合规

- 案卷、姓名、地址、电话全部虚构；不接任何真实警情、真实当事人数据。
- 只做训练与演练，不替代真实执法决策；生成的"协议书"是训练模拟文本，不是法律文书。
- 不做出警、处罚、拘留等结论；调解不成时给出"依法告知并转其他途径"的合格结局。
- 日志只记 `case_id`、维度名、分值，不记当事人姓名与对话原文。

更多：`docs/QA_通关报告.md`（十场遍历结果）、`docs/部署说明.md`（上线步骤）、`docs/COMPLIANCE.md`（合规红线）、`docs/答辩脚本.md`。
